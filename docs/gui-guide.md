# 桌面 GUI 使用说明

## 启动

Windows 双击项目根目录的 start-gui.cmd。也可以双击 FunSportWorld.pyw，或运行：

    python -m funsport gui

无参数的 python -m funsport 现在也会打开 GUI。python -m funsport help 和原有 CLI 子命令继续可用。

要求 Python 3.8+（带 Tkinter）以及 requirements.txt 中的依赖。当前通过源码启动，不提供独立EXE；无需额外安装GUI框架。启动脚本优先使用项目的.venv，否则使用系统pythonw/pyw。

## 第一次使用

1. 打开“设置与登录”，填写账号、城市及所需配置，点击“保存设置”。已有配置会保留未知字段和设备标识，不自动重建设备。
2. 填写密码后点击“登录”。若要保存在本机，先勾选“记住密码（本地明文）”并保存。保存会清空密码输入框；未记住密码时，登录前需重新输入。
3. 查询数据需要已有会话。启动窗口本身不联网，点击只读查询也不会偷偷自动登录。

密码输入为空时：同账号且已勾选记住密码，保存设置会保留原密码；取消记住密码会清除保存的密码。高德 Key 留空表示保留，只有勾选“清除”才删除。环境变量 FUNSPORT_AMAP_KEY 仍优先于文件中的 Key。

纬度和经度使用 BD-09，必须一起填或一起清空。清空会删除所存坐标并失效校园缓存；后续未配置坐标时，原工具仍会使用它的默认定位锚点，不保证就是你的学校。

## 退出登录与换设备

1. 在“设置与登录”点击“退出登录”并确认。GUI 会在后台使用当前账号的 uid/token 调用 POST /api/v6/user/logout；CLI 的 logout 共用同一个退出实现。
2. 仅在服务器返回业务成功码 10000 后，才删除本地会话、清空内存认证及 GUI 中的旧方案、点位和记录，并显示“服务器已确认退出”。保存的密码设置不变，输入框里的临时密码会清空。
3. 网络超时、响应无法验证或服务器拒绝时，不删除会话，也不显示退出成功。超时代表结果未知，不能据此断言服务器仍登录或已退出；本地凭据保留以便重新请求退出。CLI 会返回非零退出状态。
4. 服务器成功但本地文件删除失败时，界面单独提示“服务器已退出，本地清理失败”。不要把这个状态当成服务器退出失败，也不要继续使用旧会话。
5. GUI 换账号保存设置或直接登录其他账号前，必须先完成旧账号退出。不会为了切换账号而只删除旧凭据；首次保存当前已登录账号的设置不受影响。

若旧版已经删除会话，新版无法凭空找回令牌、补发那个会话的退出请求。此时需要通过官方App提供的设备或账号恢复渠道处理。离线测试不证明另一台设备能否随即登录；服务器可能还有其他登录限制。

退出使用api/v6/user/logout，不调用删除账号的userLogout接口。

## 四个页签

| 页签 | 已实现 |
| --- | --- |
| 跑步 | 在线方案与高德轨迹预览；地图、距离和时长概览；方案明细；确认提交同一在线方案；本地时间检查开关 |
| 记录与诊断 | 记录列表、按 ID 查询、服务端达标状态、点位字段检查、只读打开本地 JSON |
| 数据查询 | 学校跑步策略、学期完成度、个人日榜、AI 运动项目列表 |
| 设置与登录 | 账号、密码保存选择、城市、坐标、高德 Key、提前范围、登录与服务器确认退出 |

地图底图通过高德静态地图Web服务获取，轨迹在本机叠加，不代表已经真实跑过。普通轨迹显示为绿色；灰色、红色段按当前APK可读地图规则区分类型。用户已确认打卡点显示恢复；后续路线修复的App效果仍待核对。

## 先预览再提交

1. 填好参数，点击“在线预览”。此步骤会读取策略和点位，按需请求高德路线；不提交记录、不上传 OBS。策略或点位接口本身也可能因非开放时段返回 11016。点位可复用同账号、同校园且 5 分钟内的缓存，避免反复预览触发限流；请求失败不会回退过期缓存。
2. “地图预览”显示轨迹、起终点和编号打卡点；“方案明细”显示实际距离、时长、开始结束时间、步数、配速、随机种子和点位最近采样距离。
3. 检查后点击“提交此方案”，再次确认。提交复用这份冻结的数据，不重新随机生成。可以用方案 ID 对照前后是否一致。
4. 改动参数、账号或设置后，旧方案失效。超过 10 分钟也必须重新生成。已经进入提交请求的方案不会允许重试，即使请求超时；先查询记录确认结果。

点位“源通过状态”来自原始字段，不会根据靠近程度自动改成已通过。最近采样距离只表示几何距离，不是官方打卡判定，也不是采样间线段的最短距离。

### 顺序打卡点显示兼容修复

重启工具后重新生成在线方案，不复用旧的999方案。“方案明细”现在显示跑步策略和点位顺序来源：

- policy=1按顺序点处理；policy=0按随机点规则处理，允许任意顺序但生成时必须覆盖固定点和至少两个普通点。源顺序全部缺失、null或999时，仅在policy=1下按照本次交给高德的途经点列表，从0编号；路线、预览和上传使用同一份顺序。
- 源顺序完整时保留原编号，并按它调整实际途经列表；其他policy不重新编号。
- 已有顺序和缺失顺序混杂、重复、跳号、负数、非整数或超过5个点时停止，避免覆盖源规则或导致App编号图标越界。
- 提交前还会检查冻结点位与包装是否一致。遇到“请重新生成方案”时不会先发请求，也不会偷偷改变旧预览。

这只处理已查明的显示兼容条件，不改变isPass、policy或服务器判定，不修改已上传的历史记录。policy=2仍需原生终点判定，不能用随机或顺序点规则替代。不要为验证而重复上传旧记录。

### 路线闭合与画法

新版有序路线不再随机插入会少累计里程的无效点，也不随机标记越界、打卡或恢复事件。方案明细显示完整环长与已覆盖整圈数；预览按上传坐标的同一精度及已核实的历史地图抽样规则绘制。

“完整覆盖一圈”和“起终点重合”不是一回事：一圈加部分路程会覆盖闭环，但终点停在途中。工具不会只在画布上额外画一条首尾直线。重启后重新生成预览才能使用新逻辑，已上传记录保持原样。详细说明见[路线几何](route-geometry.md)。

## 11016 与轨迹预览

11016 是服务器业务拒绝，不是本地窗口校验。以前“允许有效时间外提交”的名字容易产生误解，现已改名为“跳过本地时间检查（测试）”。它不能改变服务器规则。

在线生成首先请求 /api/v70103/runModePolicy，之后才生成轨迹。这个策略请求不含轨迹 startTime，所以修改轨迹开始时间不能改变该请求。旧错误只有错误码和消息，无法单凭那一句证明具体是哪个接口失败；新提示会显示接口路径与阶段。

只测试轨迹时，可以点击“轨迹预览”：

1. 自动切换到手动参数，使用当前账号、学校和位置匹配的已有点位缓存。
2. 不访问运动服务的策略、点位或提交接口；会请求高德步行 API，或使用 24 小时内且来源、顺序、连续性和内容摘要都通过校验的高德路线缓存。
3. 点位缓存即使过期也可用于轨迹预览；明细显示缓存时间和“仅轨迹预览，不可提交”。点位缓存不是当前学校规则，且与高德路线缓存是两个文件。
4. 提交按钮禁用，后端也拒绝提交这种预览；打开测试开关同样不能提交。需要在线记录时，应在开放时段重新生成在线方案。
5. 没有匹配点位缓存时停止，不向运动服务补取，也不猜测其他账号缓存的归属。请在开放时段先使用“读取点位”。预览复用本机已有会话，不会自动登录。

所有生成入口均使用高德步行路线。没有有效路线缓存时需要可用的高德 Web 服务 Key。路线请求失败、分段断线或无法闭合时停止，不再悄悄使用拟合环。CLI 的 --use-map 仅作为兼容参数保留。

路线检查中的 3m 接缝、100m 端点偏离以及折线里程容差均为本工具的保守完整性检查，不是高德保证值或官方打卡规则。返回异常路线会停止；不会自行拉直断路以强行生成。

本轮移除了点位请求额外的 sportType 参数。在线读取将自动刷新旧请求版本的点位缓存，无需删除整个 .funsport 目录。只预览仍可使用匹配账号的旧点位缓存，但不代表已采用新版请求结果。

## 不同道路与种子

重启后将“随机种子”设为0再生成预览。它现在同时影响高德候选道路选择和采样，而不只是路线上的微小抖动。固定数字在点位与候选集不变时会选择同一道路；有限候选也可能重复。

“方案明细”显示道路指纹、每段候选数量及组合编号。缓存命中也会按种子选路，不必手工清空缓存。第一次使用会按需将旧的单路线缓存更新为候选缓存，失败时不删除旧文件、不影响账号。

若显示各段仅一条有效道路，当前点位顺序下没有官方备选；不会靠调乱学校打卡顺序或人工画岔路制造变化。备选可能更长或共用大部分道路，检查预览的实际里程、时长与跑区后再决定。详见route-variation.md。

## 坐标一致性

- 地图、路线端点和打卡点优先使用接口提供的有效 GCJ-02 坐标；缺失时才由 BD-09 转换。内部统一使用“纬度、经度”，高德 HTTP 参数才写成“经度、纬度”。
- 当两套源坐标不一致时，采用原生 GCJ-02，并派生一致的 BD-09 用于生成器；不再分别用两套互相冲突的位置画点和路线。
- “方案明细”显示坐标来源、最大差异及超过 5m 的点数。离线 JSON 诊断也提示冲突。5m 是本工具的提示阈值，不是官方打卡阈值。
- 转换增加迭代校正以减少正反数值残差。数值往返一致不意味着真实 GPS 或服务器点位同样精确；旧缓存或错误标注坐标系仍需核对。

## 地图与测试开关

- 底图需要有静态地图权限和可用额度的高德 Web 服务 Key。已有 Key 时在线预览后自动加载，也可点“加载底图”重试。轨迹预览不会自动加载底图。
- “+”“-”改变缩放，“适配”把轨迹和点位放入视野。适配后可重新加载底图。底图失败、缺少 Key 或离线时，仍保留轨迹图和方案明细。
- 底图请求只发送 Key、地图中心、缩放及图片大小，不发送完整轨迹、账号密码或登录令牌。高德路线规划是另一项既有功能，会使用路线端点。
- “跳过本地时间检查（测试）”默认关闭。对已生成的在线方案，可以忽略本地有效时段检查后确认提交；切换此开关不会重新生成轨迹，也不能越过服务端的 11016。
- 此开关只跳过本地有效时段检查，不会修改学校规则，也不保证服务端认可。未来记录、过期方案、账号不匹配和重复提交仍会被拒绝。
- 无需为了查看轨迹而提交记录。在线预览仍可能受服务器策略/点位接口的时段限制；具备匹配缓存的轨迹预览不依赖这些运动服务接口，但仍需要高德路线或有效路线缓存。

AI 提交、其他榜单类型、违规查询等高级操作仍在原 CLI 中，本轮没有给所有 CLI 子命令逐一增加表单。

## 结果与错误

- “记录已提交”表示服务端已返回记录 ID；不等于打卡成功。
- “OBS 1/2”表示只有一个对象上传成功，不能当成全部上传完成。
- “详情读取成功”表示能读到详情；complete 和打卡点字段仍单独检查。
- 点位字段存在只说明有数据，不代表官方 App 已绘制图标。字段缺失也可能只是接口返回摘要。
- 后台任务进行时锁定参数和操作按钮，防止连点和中途换账号。完成或失败后恢复。网络任务尚未结束时，窗口不会直接关闭。
- 提交不明或详情失败时不要直接重试，先根据已有记录 ID 查询，防止重复记录。

配置损坏时 GUI 会拒绝覆盖原文件。每个 JSON 文件采用临时文件加原子替换；多个不同文件并不是数据库事务，磁盘故障时仍需检查保存状态。

## 验证

    python -m unittest discover -s tests -v
    python -m tests.gui_smoke

测试不会使用真实 .funsport 数据。视觉验收在 Windows 上使用已安装 Pillow 的窗口截图接口，输出到 .artifacts。业务代码使用 Tkinter，不依赖该截图接口。实际官方服务登录、提交和 App 显示仍需用户自行核对。

最新结果：168项隔离测试通过，包含17项候选道路、18项顺序点位及14项路线/历史连线回归。两种尺寸的10种页面状态通过布局和像素检查，已查看新的道路指纹与组合信息。没有请求真实高德路线或提交运动记录，没有构建独立EXE；校园实际备选道路仍待用户确认。

## 初学者需要理解的三个知识点

1. 预览必须是待提交数据的快照。若提交时重新随机生成，用户检查的轨迹就不再是实际上传的轨迹。
2. BD-09 与 GCJ-02 是不同坐标系。底图、轨迹和点位必须在同一坐标系中绘制，否则看起来会偏移。
3. 跳过本地时间检查不等于服务器接受；请求超时也不代表没有写入，不能直接再次提交。

全部新增和改动函数的逐项说明见 functions.md；函数内部也有用途注释。
