# 道路变化与随机种子

## 为什么之前总是同一道路

原先随机种子只传给轨迹生成器，改变采样位置、速度和步频；高德请求没有开启备选路线，解析只读取paths[0]，缓存也只保存这一条闭环。所以即使换种子，实际道路仍然相同。

这与“不同坐标采样”“绕同一路线多跑一圈”“从另一个点出发”不同：那些变化不一定换了道路。

## 本次处理

1. 高德v5步行请求设置alternative_route=3，读取最多三条候选。官方文档说明不传时默认只返回一条；并非所有路段都有三条可用路线。
2. 同一个HTTP响应里解析各条候选，不为了三条路线分别发送三次请求。v5失败仍可回退v3；回退后可能只得到一条路线。
3. 原始点位顺序保持不变。种子选择相邻点之间的候选道路，不随机打乱学校规定的打卡顺序，也不改position或isPass。
4. 缓存保存每段候选，而不是固定整条闭环。缓存命中后仍按本次种子选路，不必为换种子重复读取Key或重新请求地图。
5. 每段来源、坐标、长度合理性和端点仍校验；拼接时保留3m接缝检查与闭合检查。某个组合断线时尝试其他组合，不补画跨区域直线。最多尝试512种组合，正常5个点、每段3条的243种组合在范围内。
6. 方案冻结后，预览、HTTP和OBS继续使用同一轨迹及点位包装；提交时不重新选路。

官方依据：高德《路径规划2.0》中的“步行路线规划 / alternative_route”参数。请求条数并不代表服务计费保证，仍以高德规则为准。

参考页面：https://lbs.amap.com/api/webservice/guide/api/newroute

## 怎么使用

- 重启工具后重新生成预览。把“随机种子”保持为0，每次准备方案会取得新的种子，同时用于选路和采样。
- 填固定种子，例如42，在点位顺序和候选集不变时会选择相同道路；这是为了可以复现，不是随机功能失效。
- “方案明细”新增道路指纹、每段候选数量和道路组合编号。道路指纹变了表示最终道路折线数据改变，不只是时间、速度或采样抖动改变。
- 如果显示“每段只有一条有效道路”，当前固定点位顺序下没有可切换的官方备选。不能保证每次都不同，也不会人为画不存在的岔路。
- 不同组合可能共用大量路段；可选集合有限，换不同种子也可能选中同一组合。备选道路可能更长，实际里程与时长以新预览为准，并核对学校跑区。
- 轨迹预览也支持按种子选路，但仍无学校策略、不可提交。不要为测试选路而重复上传旧记录。

## 缓存与数据保护

缓存文件名仍为campus_loop_bd.json，结构从schema3升级为schema4，继续验证点位顺序、地图来源、24小时时效和完整内容摘要。换种子只读缓存，不延长有效期、不改写原始点位缓存。

该文件仍是本地明文数据，现在包含更多候选道路的精确坐标；没有新增加密存储。.funsport目录已被.gitignore排除，不要分享或提交整个数据目录。新选路日志仅报告数量和道路指纹，不输出候选坐标或Key。

旧schema3没有备选数据，因此需要重新获取候选；仅在新道路能有效闭合后才原子保存。请求失败或组合均不连续时，旧文件保留但不会冒充新的候选缓存使用。无需删除整个.funsport目录，账号和会话不受影响。

## 验证范围

全套168项隔离测试通过；在模拟高德响应中验证了不同种子确实改变道路几何、同种子复现、只返回一条时不伪造变化、缓存命中不联网，以及点位顺序/通过状态保持不变。

补充验证了五点三候选的第243种组合、512次枚举上限、精确24小时过期边界，以及首次HTTP响应选路与缓存选路相同。两种窗口尺寸的10种页面状态通过，新的道路信息在最小窗口中可滚动查看。

没有读取真实账号配置、使用真实高德Key、请求实际地图路线或上传运动记录。不能据此保证用户校园一定存在多条可用道路，也没有声称已完成官方App真机验收。

复现命令：python -m unittest -v tests.test_route_options。测试不使用真实账号或地图Key。
