# 路线闭合与预览一致性

## 修复内容

闭合的道路规划线不代表采样轨迹已经覆盖整圈。旧生成器在拟合目标里程后随机插入不累计里程的无效点，消耗了时间却少走距离；有序路线现在不随机标记无效、越界、打卡或恢复事件。

- 有序模式使用普通点及明确起终点。起点为路线起始位置、时间0与累计里程0；终点按实际弧长取样，不瞬移回起点。
- 速度与里程不兼容、或拟合无法达到规划目标时停止，不用最后一点的大跳跃凑距离。
- 十秒里程统计采用实际累计值；不足十秒的尾段保留实际时长和里程。
- 预览使用与上传相同的七位GCJ坐标，并按照已核实的Android 7.3.70可读历史地图规则跳过无效点、抽样与着色，起终点来自显式类型。
- 部分地图桥接实现仍不可读，因此不能只凭本地测试保证所有设备的最终画法完全一致。

打卡点顺序和通过状态独立处理；本修复不改isPass、学校policy或历史记录。

## 闭环的含义

目标恰好是一整圈时，采样首尾相接。一圈加部分路程仍覆盖完整闭环，但终点可能留在途中；工具不会仅在画布上加一条直线制造假闭合。

方案明细显示完整环长及已覆盖圈数。变更参数后需重新生成预览，提交使用该快照，不再次随机规划。道路选择与种子的关系见[道路变化](route-variation.md)。

## 验证

回归覆盖30个此前可能不足一圈的种子、一圈与部分额外路程、弧长终点、累计里程与窗口统计、OBS解码坐标一致性，以及历史地图过滤和颜色规则。GUI检查覆盖1120x820和960x760两个窗口尺寸。

复现：python -m unittest -v tests.test_route_geometry tests.test_map_preview。

没有使用真实高德Key或上传真实运动记录进行自动验收。新方案的App效果仍需在实际环境核对，不应重复上传旧记录作为测试。
